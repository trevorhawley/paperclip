# Roadmap toward the north star (draft, 2026-11-26)

Ranked by impact on Trevor's daily use, with the smallest useful version of each first. "Have" means it's confirmed in the code today. "Gap" means our read of what's missing, which isn't verified end to end.

## 1. Coordinator experience in Paperclip chat (confirmed #1 by Trevor)

| Ingredient | Have | Gap |
| --- | --- | --- |
| Role prompt | Agents have instruction bundles; Slack/voice chats get communication guidance (`chat-communication-guidance.ts`) | No "coordinator" role or guidance for in-app chat |
| Instant acknowledgement | Receipt reactions exist for Slack, Telegram and GitHub (`chat-receipt-reactions.ts`) | No reactions or "on it" receipts in native Paperclip chat |
| Delegation into threads | Agents create and assign subtasks; explicit delegation from ChatGPT Voice passed production acceptance | Delegated work isn't shown as named threads with a checklist in the chat |
| Event-driven updates | Heartbeat wakes on assignment, comments and mentions | The chat doesn't post a short digest when a child task finishes or blocks |
| Decision cards | `ask_user_questions` and `request_confirmation` interactions, resolvable in the Inbox | Not surfaced inline in chat as compact cards |
| Memory every turn | Optional read-only Trevor AI Memory provider (tested, not live) | Not loaded into the coordinator's context; live connection needs Trevor's OK |
| Thread-centric UI | Agent chat, task threads, Inbox overview | No chat-plus-threads side panel |

**Smallest useful version (v0):** a "Coordinator" agent preset with role instructions (short replies, act first, delegate deep work, one-line acknowledgements) plus a child-task digest. When a task it created finishes or blocks, it posts one line in its chat. Next come instant receipts in native chat, then inline decision cards, then the threads side panel.

## 2. Cheap front door through the ChatGPT app

ChatGPT read, passive write and explicit delegation already work in production. Next: one-call handoff ("do this in Paperclip") that returns a task link, and results flowing back as a short summary the next time Trevor asks "what's on".

## 3. Mirror ClickUp

v0: read-only. Show Trevor's ClickUp tasks for today and his ONE Thing in the Inbox overview. Later: two-way status sync for tasks Paperclip agents own.

## 4. Best-fit model routing

v0: a per-task "model tier" (cheap, standard or deep) that the coordinator sets when delegating, mapped to configured agents. Never default to gpt-6-astra.

## 5. Memory loaded every turn

Turn on the Trevor AI Memory provider read-only for the coordinator. This needs Trevor's explicit yes for the live connection. Then add a small "preferences" file the coordinator reads every turn and updates when he corrects it.

## 6. Google Docs on projects

Link a project's master Docs and show them in the project Context tab, so agents and Trevor share the same source.

## 7. Glanceable everywhere

Apply FORK-UI-DENSITY.md screen by screen. Inbox, Context, Tasks and the sidebar are done. Next come agent detail, routines and the dashboard.

## Not now

Deep-dive software building inside Paperclip (that stays in Claude Code), KI-1 and KI-2a/b fixes (deferred by Trevor), and isolated workspaces in production (TRE-27 stays blocked).
