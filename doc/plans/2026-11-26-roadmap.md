Ranked by impact on Trevor's daily use, with the smallest useful version of each first. "Have" means it's confirmed in the code today. "Gap" means our read of what's missing, which isn't verified end to end.

## 1. Coordinator experience in Paperclip chat (confirmed #1 by Trevor)

| Ingredient | Have | Gap |
| --- | --- | --- |
| Role prompt | Agents have instruction bundles; Slack/voice chats get communication guidance (`chat-communication-guidance.ts`) | No "coordinator" role or guidance for in-app chat |
| Instant acknowledgement | Receipt reactions exist for Slack, Telegram and GitHub (`chat-receipt-reactions.ts`) | No reactions or "on it" receipts in native Paperclip chat |
| Delegation into threads | `suggest_tasks` proposals, `chat_task_handoffs`, and a per-chat tasks panel (`CoordinatorConversationTasksPanel`, `/issues/:id/chat-handoffs`) | Live progress per thread is a status, not a step checklist |
| Event-driven updates | Done handoffs wake the chat to report (`chat_task_completed`); blocked handoffs post a zero-token system line (PR 24) | Batching several updates into one digest |
| Decision cards | Interactions render in chat, with pending-question and decision-receipt projections (`CoordinatorChatPendingQuestions`, `CoordinatorChatDecisionReceipts`) | Density pass to match FORK-UI-DENSITY.md |
| Memory every turn | Optional read-only Trevor AI Memory provider (tested, not live) | Not loaded into the coordinator's context; live connection needs Trevor's OK |
| Thread-centric UI | Agent chat with a Tasks tab for its handoffs, task threads, Inbox overview | Open a handed-off task beside the chat (split view) |

**Token-efficiency requirements** (how a long coordinator chat stays cheap):
- Heavy work runs in threads, and only short reports come back to the coordinator. Tool output and file reads never enter the front-door context.
- Stable context (role prompt, memory and preferences, project map) sits first and uses prompt caching, so repeat turns cost a fraction.
- Context rollover: when the coordinator's context grows past a threshold, it starts fresh from a summary plus persistent memory instead of carrying the whole history.
- Replies stay short by default, and each wake carries one new event, not the full history.

## 1b. "Why isn't this running?" (no silent blocking)

A built-in check on chats and tasks that tests the common hidden blockers and shows the answer with a fix button: agent paused, instance runs switched off (worktree lock), missing AI connection or key, budget reached, blocked by another task, project or task paused, failed last run. Done so far: paused-agent status and chat notice, and Resume answering waiting messages (PR 27). Next: make "Queued" explain itself when scheduling is suppressed. This also seeds an in-app troubleshooting guide for non-technical users.
